单协议的各层次

每个中间层协议内部都由相同的八层构成（自顶向下）。严格地说，只有 6 层属于本协议自身的内部层次（服务接口层、网络层、链路层、复用层、协议接口层、端路层）；载荷层与承载层是外部层次——它们指向相邻的上层 / 下层协议，是递归的接口。

层次 说明
载荷层（外部）本协议向上交付 / 接收的数据本体；上层协议的数据作为载荷在本层传递。本协议对上层协议完全不了解——上层只是不透明的纯数据载荷，本层无需知道上层是谁。外部层次：指向紧邻的上层协议，不属于本协议的内部功能。
服务接口层向上层提供的接口契约（拓扑 / 数据格式 / 服务承诺 / 参数 / 建链 / 通信 / 拆链），上层经它调用本层服务。拓扑——端到端连接或全连通网络两种类型；数据格式——数据包、连续字节流或连续比特流；服务承诺——如 TLS 承诺安全、TCP 承诺可靠、IP 承诺尽力而为；参数——双向：既有上层传递给下层的下行参数（如调用时提供的目标地址、端口），也有上层从下层读取的上行参数（如 MTU、链路状态等上报量）。类似软件库对外暴露的函数签名——本层定义参数，调用它的上层既能提供参数值、也能读取状态值；接口是单边定义的，由下层定义、由上层（调用者）消费。
网络层转发与寻址决策：控制面（路由 / 转发规则）与转发面（查表、转发、封装解封装）。
链路层单链路上的语义：连接状态、差错检测、校验、重传、流控等。
复用层向上提交单链路、向下提交聚合后的多链路，把下层多条承载通道复用 / 聚合为一条。
协议接口层通信两端同层次端点之间的接口——本层端点与对端同层端点对接，交付本层数据单元（如 TCP 向对端 TCP 交付 TCP 段、IP 向对端 IP 交付 IP 数据报）。本层并非独立的功能层：它不维护状态、不做决策、不加工数据，而是数据流的观察截面——本层封装（加头）在此成形，数据以本层数据单元的形式在对端同层之间交换。这是对等（peer）通信而非调用关系，因此无需像服务接口那样携带参数 / 初始化契约——对端同层既不是调用者也不是被调用者，契约仅含「交付」（本层数据单元）。封装式层次为离散 PDU（报文 / 记录 / 段 / 数据报 / 帧），连续式层次（编码调制、光波）为比特流 / 光信号。与下层承载的对接（调用下层服务接口、提供寻址参数）由端路层负责；逐级递归直至对端。连接建立 / 握手（如 TCP 三次握手）属于协议自身的连接管理，由链路层与协议接口层承载，不在端路层。
端路层本协议与下层协议咬合（互锁）的层次——调用下层协议的服务接口，在下层承载网络上建立端到端通道；本层在此扮演调用者（如同齿轮嵌入下层协议的服务接口插座）：下层服务接口定义了参数，端路层负责提供参数值并调用。端路层的意义：在双栈主机上（同时运行 IPv4 与 IPv6 两个 IP 栈），上层协议（如 TCP）必须经端路层选择承载的 IP 栈——"向下选择哪个下层承载"正是端路层存在的意义。通道生命周期分四阶段：规划——指定下层承载寻址参数（如 IP 选好下一跳后指定其目标IP、以太网指定目标MAC）即可视为端到端通道确立；初始化——调用下层服务接口前的地址解析 / 参数准备（如 IP 在以太网上先经 ARP 解析出下一跳的目标 MAC）；正常通讯——每次交付时向底层提供承载寻址参数（如 IP 每包指定下一跳目标IP、以太网每包指定目标MAC）；拆除通道——通讯结束时经下层服务接口释放通道（如关闭连接、删除通道状态）。若下层承载本身已是端到端，本层不再另行建路，仅负责发起建链。注意：本协议自身的连接建立 / 握手（如 TCP 三次握手）属于协议自身连接管理，不在本层。
承载层（外部）本协议以下层整体作为承载链路；在递归模型中，下层即本层的承载。本协议不关心下层的内部机制，但必须了解其服务接口（拓扑 / 数据格式 / 服务承诺 / 参数 / 建链 / 通信 / 拆链），才能经端路层调用它。外部层次：指向紧邻的下层协议，不属于本协议的内部功能。

递归结构

协议同构 —— 每个中间层协议都具有完全相同的八层结构（其中 6 层为内部层次，载荷层 / 承载层为外部层次），同一结构在不同层级重复出现，是本模型的递归基础。

双向递归 —— 向下递归形成承载链（每一层把下层当作承载链路），向上递归形成传输链（每一层把上层当作载荷）。从任一层协议视角看，整个栈可折叠为「载荷 → 本协议 → 承载」的三层结构；把本协议展开，内部又是同样的八层，如此层层递归。

递归终点 —— 向上终止于数据层（不再封装，数据即载荷本身），向下终止于介质层（光纤，不再承载）。
