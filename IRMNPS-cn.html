单协议的各层次

每个中间层协议内部都由相同的八层构成（自顶向下）。严格地说，只有 6 层属于本协议自身的内部层次（服务接口层、网络层、单链路层、复用层、聚合链路层、端路层）；载荷层与承载层是外部层次——它们指向相邻的上层 / 下层协议，是递归的接口。

层次 说明
载荷层（外部）本协议向上交付 / 接收的数据本体；上层协议的数据作为载荷在本层传递。本协议对上层协议完全不了解——上层只是不透明的纯数据载荷，本层无需知道上层是谁。外部层次：指向紧邻的上层协议，不属于本协议的内部功能。
服务接口层向上层提供的接口契约（拓扑 / 服务承诺 / 参数 / 建链 / 通信 / 拆链），上层经它调用本层服务。拓扑——端到端连接或全连通网络两种类型；服务承诺——如 TLS 承诺安全、TCP 承诺可靠、IP 承诺尽力而为；通信——本层数据交换的调用签名：每次传输的数据形态（数据包 / 连续字节流 / 连续比特流 / 光信号等）、方向与携带量（交付的数据单元：HTTP 报文 / TLS 记录 / TCP 段 / IP 数据报 / 以太网帧）都在该项给出，不含目标地址；参数——双向：既有上层调用本层时传递的下行参数（目标地址 / 端口 / 分用标识——目标主机:端口、目标IP、目标MAC、Type、协议号等），也有上层从下层读取的上行参数（如 MTU、链路状态等上报量）。类似软件库对外暴露的函数签名——本层定义参数，调用它的上层既能提供参数值、也能读取状态值；接口是单边定义的，由下层定义、由上层（调用者）消费。
网络层转发与寻址决策：控制面（路由 / 转发规则）与转发面（查表、转发、封装解封装）。
单链路层复用层上方：本协议在同层对端之间一条解复用后的单条逻辑链路 / 会话上的语义——连接状态、差错检测、校验、重传、流控等（逐条单链路各自管理，如 TCP 每连接、802.11 每站点链路）。
复用层位于单链路层与聚合链路层之间：向上提交单链路、向下提交聚合后的多链路，把下层多条承载通道复用 / 聚合为一条；单链路层管“解复用后的一条”，聚合链路层管“复用后的一条”。
聚合链路层复用层下方：把本层全部单链路复用聚合后形成的那一条聚合链路的点到点收口——整链整体校验 / 传输信封 / 对整条聚合信号起作用的增强（如 FCS 覆盖 802.1Q 聚合帧、整段 WDM 的 EDFA / 色散补偿）。本层向下交付的本层数据单元（对端同层端点之间交换的报文 / 记录 / 段 / 数据报 / 帧等）亦在此收口，由端路层调用下层时随路交付。下层协议正是把这条聚合链路当作它的一条单链路来承载，故聚合链路的可靠与增强也常落在承载侧。
端路层本协议与下层协议咬合（互锁）的层次——调用下层协议的服务接口，在下层承载网络上建立端到端通道；本层在此扮演调用者（如同齿轮嵌入下层协议的服务接口插座）：下层服务接口定义了参数，端路层负责提供参数值并调用。端路层的意义：在双栈主机上（同时运行 IPv4 与 IPv6 两个 IP 栈），上层协议（如 TCP）必须经端路层选择承载的 IP 栈——"向下选择哪个下层承载"正是端路层存在的意义。通道生命周期分四阶段：规划——指定下层承载寻址参数（如 IP 选好下一跳后指定其目标IP、以太网指定目标MAC）即可视为端到端通道确立；初始化——调用下层服务接口前的地址解析 / 参数准备（如 IP 在以太网上先经 ARP 解析出下一跳的目标 MAC）；正常通讯——每次交付时向底层提供承载寻址参数（如 IP 每包指定下一跳目标IP、以太网每包指定目标MAC）；拆除通道——通讯结束时经下层服务接口释放通道（如关闭连接、删除通道状态）。若下层承载本身已是端到端，本层不再另行建路，仅负责发起建链。注意：本协议自身的连接建立 / 握手（如 TCP 三次握手）属于协议自身连接管理，不在本层。
承载层（外部）本协议以下层整体作为承载链路；在递归模型中，下层即本层的承载。本协议不关心下层的内部机制，但必须了解其服务接口（拓扑 / 服务承诺 / 参数 / 建链 / 通信 / 拆链），才能经端路层调用它。外部层次：指向紧邻的下层协议，不属于本协议的内部功能。

递归结构

协议同构 —— 每个中间层协议都具有完全相同的八层结构（其中 6 层为内部层次，载荷层 / 承载层为外部层次），同一结构在不同层级重复出现，是本模型的递归基础。

双向递归 —— 向下递归形成承载链（每一层把下层当作承载链路，本层的聚合链路恰是下层的一条单链路），向上递归形成传输链（每一层把上层当作载荷）。从任一层协议视角看，整个栈可折叠为「载荷 → 本协议 → 承载」的三层结构；把本协议展开，内部又是同样的八层，如此层层递归。

递归终点 —— 向上终止于数据层（不再封装，数据即载荷本身）；向下终止于介质层光纤的单链路——那根未跳纤改向、经熔接/机械接续成型的点对点纤芯（介质层以上各层，含光纤层的配线网，都已是可任选对端的全连通网络）。

横切关切与跨层策略

八层单元是结构槽位（角色 / 位置），而非机制清单。模型的边界在于：它描述的是“任意中间层协议的递归转发 / 承载结构”，而非枚举现代网络中的全部机制。现代网络中的许多行为——拥塞控制、QoS 调度、故障保护、安全隔离、会话管理——是横切关切（cross-cutting concerns）：它们跨越多个图层，不天然对应某一个固定图层。每一类横切关切都在八层单元中有明确落点，由相应图层协同实现：

横切关切 服务接口层（承诺） 网络层 单链路层 复用层 聚合链路层 端路 / 承载层
拥塞控制承诺“尽力而为”下的公平与低丢包网络状态反馈（ECN 标记、丢包）重传、流控（含拥塞窗口 CWND 自适应，逐连接）———
QoS 调度承诺的量化分级（时延 / 吞吐 / 抖动）按 QoS 约束选路队列调度（WFQ/DRR）、整形、限速汇聚带宽分配——

上表说明两点：其一，模型并非不能描述这些行为——每一项都能在八层单元中找到明确落点；其二，它们之所以“不能独立成一个图层”，恰恰因为它们是横切关切——强行为其单独设层（如同 OSI 把每个功能摊进固定层）反而会破坏模型的同构性，并陷入“某行为究竟属于哪一层”的无休止争论。模型的选择是：以八层结构为骨架，让横切关切按所在层位归位、跨层协同。

参数传递与控制/管理面的边界

日常的寻址 / 参数永远沿递归栈逐级下传，绝不跳层。目标地址与端口由上层在调用时给出（如 HTTP 的 URL 指定对端主机与端口 http=80 / https=443），经每一跳“上层端路 ↔ 下层服务接口”逐级传递：一层只消费属于自己的部分（如 TCP 用目标端口做会话复用），把其余参数翻译成下层命名空间后继续下传（如目标IP 在 IP 层被消费为路由依据，再经 ARP 翻译成以太网的目标MAC），直到抵达“消费它的层”即止。

真正跳层的只有控制/管理面——即图中中栏的旁路纵轴。ASON-UNI 建链信令（以太网客户 → 光波 ASON 控制面）与 NMS 的收发器配置都越过中间层直连，与数据面递归正交；它们是控制面 / 管理面的事，不是服务接口的参数传递。

为什么这种协调必须“带外”？因为承载层若对上层数据透明——如光波层只把 λ 信号当作纯光传送、不解析带内比特——就读不懂“随数据携带”的带内请求。要给它下达建链 / 配置指令，只能走独立的带外通道（ASON-UNI 控制面信令 / NMS 管理面配置）。带内 vs 带外的判据：该层是否解析途经它的比特。
