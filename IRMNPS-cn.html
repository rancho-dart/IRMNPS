单协议的各层次

每个中间层协议内部都由相同的八层构成（自顶向下）。严格地说，只有 6 层属于本协议自身的内部层次（卯眼层、网络层、单链路层、复用层、聚合链路层、榫头层）——它们是同一协议自身的功能分解，共同对外只露出两个面：顶上是一个卯眼层（对上层协议）、底下是一个榫头层（对下层协议）；载荷层与承载层是外部层次——它们指向相邻的上层 / 下层协议，是递归的接口。这八层是结构槽位（角色 / 位置），而非机制清单——模型的边界在于：它描述的是“任意中间层协议的递归转发 / 承载结构”，而非枚举现代网络中的全部机制。

层次 说明
载荷层（外部）本协议向上交付 / 接收的数据本体；上层协议的数据作为载荷在本层传递。本协议对上层协议完全不了解——上层只是不透明的纯数据载荷，本层无需知道上层是谁。外部层次：指向紧邻的上层协议，不属于本协议的内部功能。
卯眼层向上层提供的接口契约，与榫头层逐阶段对应——上层经它调用本层服务。
  • 服务承诺——契约品质：TLS 承诺安全、TCP 承诺可靠、IP 承诺尽力而为。
  • 规划——建链前的准备：本层公示自己的能力与属性（MTU、速率/双工档位、可用波长、信道、编码调制格式、光纤类型、本机IP/MAC）；上层据此读取（如 MTU）、与之协商（速率/双工、MCS/带宽/功率、信道），或两层间无法直接交换信息（被动介质）时各自静态约定配置（光纤类型 / 阻抗 / 传播损耗 / λ 通道）。参数对齐齐备，才谈得上建链。
  • 建链——本层通道的建立分四类：
    • 无连接——TCP、IP：协议本身无连接
    • 预置——以太网、编码调制、同轴、光纤，及光波的默认分支：建设期固定
    • 本层自治——WLAN 关联认证、射频调制自适应、频段复用信道选定：本层自己干完
    • 按需带外——光波 ASON-UNI 信令
    四者对上层效果一致：不需上层调用建链——故卯眼·建链 处只标类别、不写「无」；拆链同理（无连接 / 不拆（预置）/ 本层自治 / 按需带外释放）。
  • 通信——交付本层数据单元，并给出本层数据交换的调用签名：数据形态（数据包 / 连续字节流 / 连续比特流 / 光信号等）、方向与携带量（HTTP 报文 / TLS 记录 / TCP 段 / IP 数据报 / 以太网帧）；不含目标地址（目标地址属实参）。
  • 各阶段参数——建链 / 通信 / 拆链随调用提供的实参（图中一律以 参数： 标注，如 connect 的五元组、每报的目标IP/协议号、每帧的目标MAC/Type）与上行读取的运行时观测（链路状态、RSSI、CCA、冲突、信道占用）。参数不单列——它客观上就是这几次调用的实参，故并入对应阶段。
  • 接口性质——类似软件库对外暴露的函数签名：本层定义参数，调用它的上层既能提供参数值、也能读取状态值；接口单边定义，由下层定义、由上层（调用者）消费。
  • 不承诺拓扑——本层向上呈现为一个全连通网络（上层可任选对端）；对端由上层榫头层在建链时选定，并在此固化出一条端到端承载链路——故卯眼层只承诺这条链路的服务品质。
网络层转发与寻址决策：控制面（路由 / 转发规则）与转发面（查表、转发）。
单链路层复用层上方：本协议在同层对端之间一条解复用后的单条逻辑链路 / 会话上的语义——连接状态、差错检测、校验、重传、流控等（逐条单链路各自管理，如 TCP 每连接、802.11 每站点链路）。
复用层位于单链路层与聚合链路层之间：向上提交单链路、向下提交聚合后的多链路，把下层多条承载通道复用 / 聚合为一条；单链路层管“解复用后的一条”，聚合链路层管“复用后的一条”。
聚合链路层复用层下方：把本层全部单链路复用聚合后形成的那一条聚合链路的点到点收口——整链整体校验 / 传输信封 / 对整条聚合信号起作用的增强（如 FCS 覆盖 802.1Q 聚合帧、整段 WDM 的 EDFA / 色散补偿）。本层向下交付的本层数据单元（对端同层端点之间交换的报文 / 记录 / 段 / 数据报 / 帧等）亦在此收口，由榫头层调用下层时随路交付。下层协议正是把这条聚合链路当作它的一条单链路来承载，故聚合链路的可靠与增强也常落在承载侧。
榫头层本协议与下层协议咬合（互锁）的层次——调用下层协议的卯眼，在下层承载网络上建立端到端通道；本层扮演调用者（如同榫头插入下层的卯眼）：下层卯眼定义参数，榫头层负责提供参数值并调用。
  • 榫头层的意义——在双栈主机上（同时运行 IPv4 与 IPv6 两个 IP 栈），上层协议（如 TCP）必须经榫头层选择承载的 IP 栈——“向下选择哪个下层承载”正是榫头层存在的意义。
  • 规划——建链前的准备：备齐本侧参数并对齐口径——自下层读取本层属性（MTU、本机IP、本机MAC）、与下层协商档位（速率/双工、MCS/带宽/功率）、解析出承载寻址参数（ARP → 下一跳目标MAC、DNS → 目标IP、选定地址族）。这些正是随后建链 / 通信要交付的实参。
  • 建链——调用下层卯眼前的地址解析 / 参数准备（如 IP 在以太网上先经 ARP 解析出下一跳的目标 MAC）；若下层承载本身已是端到端，本层不再另行建路，仅负责发起建链。
  • 通信——每次交付时向底层提供承载寻址参数（如 IP 每包指定下一跳目标IP、以太网每包指定目标MAC）。
  • 拆链——通讯结束时经下层卯眼释放通道（如关闭连接、删除通道状态）。
  • 与协议自身握手的区别——本协议自身的连接建立 / 握手（如 TCP 三次握手）属协议自身连接管理，不在本层。
承载层（外部）本协议以下层整体作为承载链路；在递归模型中，下层即本层的承载。本协议不关心下层的内部机制，但必须了解其卯眼（服务承诺 / 规划 / 建链 / 通信 / 拆链），才能经榫头层调用它。外部层次：指向紧邻的下层协议，不属于本协议的内部功能。

协议间的咬合

协议之间如榫卯：本协议的榫头层插入下层协议的卯眼层咬合——下层以卯眼（服务接口）开出“槽形”（定义要哪些参数、怎么调），上层以榫头（端路）提供参数值并调用；反过来，本协议的卯眼层正是上层协议榫头层插入之处。此处“上下”指协议之间的上下（相邻两个协议的咬合），不是本协议内部各层的层序。同构八层如一套同形拼块，逐个协议层层卡接、无钉无胶。

两个咬合面各对应一个外部层次：向下插入下层卯眼，即把下层协议整体当作本协议的承载层；向上被上层协议榫头插入，即把上层协议整体当作本协议的载荷层——这正是“载荷层 / 承载层是外部层次”的含义。

先对表，后建链：两头的咬合不是“上来就连”——规划阶段先把参数对齐：上层读取下层的能力与属性、双方在档位域内协商选定、被动介质则各自静态约定，并解析出承载寻址参数；齐备后才谈得上建链——建链与通信所交付的实参（五元组、目标MAC、Type、MCS / 功率……）全部产自规划期。运行期的自适应（速率自适应、信道重选）只是在该阶段议定的档位域与口径之内取值，不再重新对表。

递归结构

协议同构 —— 每个中间层协议都具有完全相同的八层结构（其中 6 层为内部层次，载荷层 / 承载层为外部层次），同一结构在不同层级重复出现，是本模型的递归基础。

双向递归 —— 向下递归形成承载链（每一层把下层当作承载链路，本层的聚合链路恰是下层的一条单链路），向上递归形成传输链（每一层把上层当作载荷）。从任一层协议视角看，整个栈可折叠为「载荷 → 本协议 → 承载」的三层结构；把本协议展开，内部又是同样的八层，如此层层递归。

递归终点 —— 向上终止于数据层（不再封装，数据即载荷本身）；向下终止于介质层光纤的单链路——那根未跳纤改向、经熔接/机械接续成型的点对点纤芯（介质层以上各层，含光纤层的配线网，都已是可任选对端的全连通网络）。

横切关切如何归位

现代网络中的许多行为——拥塞控制、QoS 调度、故障保护、安全隔离……——是横切关切（cross-cutting concerns）：它们跨越多个图层，不天然对应某一个固定图层。模型的选择是：以八层结构为骨架，让横切关切按所在层位归位、多层协同——不为其单独设层（如同 OSI 把每个功能摊进固定层），以免破坏模型的同构性，并陷入“某行为究竟属于哪一层”的无休止争论。

参数传递与控制/管理面的边界

日常的寻址 / 参数永远沿递归栈逐级下传，绝不跳层。目标地址与端口由上层在调用时给出（如 HTTP 的 URL 指定对端主机与端口 http=80 / https=443），经每一跳“上层榫头 ↔ 下层卯眼”逐级传递：一层只消费属于自己的部分（如 TCP 用目标端口做会话复用），把其余参数翻译成下层命名空间后继续下传（如目标IP 在 IP 层被消费为路由依据，再经 ARP 翻译成以太网的目标MAC），直到抵达“消费它的层”即止。

真正跳层的只有控制/管理面——即图中中栏的旁路纵轴。ASON-UNI 建链信令（以太网客户 → 光波 ASON 控制面）与 NMS 的收发器配置都越过中间层直连，与数据面递归正交；它们是控制面 / 管理面的事，不是卯眼的参数传递。

为什么这种协调必须“带外”？因为承载层若对上层数据透明——如光波层只把 λ 信号当作纯光传送、不解析带内比特——就读不懂“随数据携带”的带内请求。要给它下达建链 / 配置指令，只能走独立的带外通道（ASON-UNI 控制面信令 / NMS 管理面配置）。带内 vs 带外的判据：该层是否解析途经它的比特。
